### 1. Unified Command Protocol (Steal from the Robot Car)

* **What they do:** Simple plaintext or JSON command strings over Bluetooth Serial (`F` = Forward, `B` = Backward, `L` = Left, `R` = Right, `S` = Stop).


* **How we steal it for our Badge Agent:**
Extend your serial-bridge (`control.py`) to support quick macro shortcuts in addition to full JSON payloads. When managing badges or testing peripherals interactively, typing a raw JSON payload every time gets tedious. Adding shortcut aliases makes the agent much more ergonomic:
* `badge set_led 0 255 0 0` $\rightarrow$ translates to `{"cmd":"set_led","index":0,"r":255,"g":0,"b":0}`
* `badge scan` $\rightarrow$ translates to `{"cmd":"scan_i2c"}`



### 2. Event-Driven Telemetry Relay (Combine Robot telemetry + MQTT)

* **What they do:** Transmit state changes from the robot hardware back to the controller interface.
* **How we steal it for our Badge Agent:**
Your `badge-mqtt-bridge` (`bridge.py`) is already well-designed around a topic hierarchy (`badge/chonk/{component}/{action}`). We can expand this to mimic robotics telemetry loops:


* Publish button clicks (`SW1`, `SW2` tactile switches) as instant MQTT events (`badge/chonk/button/pressed`).


* Relay battery voltage readings or sensor states automatically so external monitoring agents (or a dashboard) can react without manual polling.



### 3. Modular Hardware Profiles / Board Definitions

* **What they do:** Clear separation of wiring configurations and motor/pin mappings.
* **How we steal it for our Badge Agent:**
Since you build different variants (ESP8266 badges vs. ESP32 WROOM breakout badges with APA102 LEDs and SSD1306 OLEDs), formalize **Board Profile JSON files** inside `skills/hardware-agent/profiles/`:


```json
{
  "board_name": "voodoo-esp32-badge",
  "mcu": "ESP32-WROOM-32E",
  "pins": {
    "apa102_data": 23,
    "apa102_clock": 18,
    "i2c_sda": 21,
    "i2c_scl": 22
  },
  "power_budget": {
    "max_led_brightness_pct": 20,
    "usb_safe": true
  }
}

```


The `firmware-builder` and `io-scanner` can then read these profiles dynamically so your agent knows what pins to test or how bright the LEDs can safely go without tripping USB current limits.
